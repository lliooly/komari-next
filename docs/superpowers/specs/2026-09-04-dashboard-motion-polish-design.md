# Dashboard A+B 动效润色设计

- 日期：2026-09-04
- 状态：方向已批准，待规格审阅

## 背景

项目已经完成语义图标反馈：刷新、保存、登录、删除等异步动作会显示 loading、成功或失败状态。本阶段不继续给静态图标增加持续运动，而是让仪表盘中的实时数据、节点列表和空间布局对变化做出克制的视觉回应，减少“面板很死板”的感觉。

本阶段沿用用户已确认的 A+B 方向：

- A：数据活力型——数值、进度、图表和在线状态随真实数据变化产生反馈。
- B：空间层次型——节点卡片、筛选结果、地图和提示区域在进入、离开、重排时产生稳定过渡。

## 目标

1. 让实时数据变化可感知，但不造成高频闪烁或视觉噪音。
2. 让搜索、分组、排序、节点上线/下线和布局变化有连续的空间过渡。
3. 复用现有 `useAnimatedNumber`、CSS transition、Framer Motion 和图表实现，不增加动画依赖。
4. 保持网格、表格、移动端和深色模式布局稳定。
5. 在 `prefers-reduced-motion: reduce` 下取消位移、缩放、渐变和绘制动画，只保留静态状态切换。

## 非目标

- 不修改后端接口、轮询频率、节点数据结构或主题配置格式。
- 不给每次轮询的所有卡片重新播放入场动画。
- 不让数字跳动、全屏闪烁、背景持续呼吸或地图所有 marker 持续脉冲。
- 不改变现有错误文案、Toast、加载骨架和语义图标反馈规则。
- 不恢复或修改 Uptime Kuma 中有意删除的 Monitor ID 展示。

## 方案决策

采用“真实变化触发 + 固定节奏动画”的方案：

- 只对参与数据变化的数值或进度元素更新动画状态。
- 节点列表的入场/离场由节点 UUID 控制；实时数据更新不能触发整张卡片重播。
- 动效时长统一限制在 160–500ms：交互切换偏快，数据变化偏柔和。
- 所有动画元素保留固定尺寸或固定占位，避免文字、按钮和卡片高度跳动。
- 不用颜色作为唯一状态提示；在线状态仍保留文本或 Badge。

## A：数据活力型

### 1. 顶部概览卡片

文件：`src/components/DashboardContent.tsx`、`src/components/CurrentTimeCard.tsx`

- 在线节点数、地区数等纯数字指标使用现有数字动画能力，在 250–350ms 内平滑过渡。
- 流量和网速等带单位文本不做逐字符滚动，采用固定宽度容器内的轻微交叉淡入，避免单位变化造成错位。
- 当前时间保持每秒更新，但不播放成功、闪烁或弹跳动画。
- 卡片仅在首次出现或可见性配置变化时做一次 180–220ms 淡入；5 秒轮询不重播卡片入场。

### 2. 节点资源指标

文件：`src/components/Node.tsx`、`src/components/AdaptiveChart.tsx`、`src/components/CircleChart.tsx`

- CPU、RAM、Disk 的圆环、进度条和柱状图继续使用平滑数值变化，单次更新控制在 350–500ms。
- 同一节点的资源数值只更新图表和数值区域，不重新挂载整个节点卡片。
- 数值变化超过合理阈值时，数值文字做一次约 180ms 的透明度/颜色强调；小于阈值的抖动不提示。
- 图表初次加载可以绘制一次，实时更新只过渡终点或当前百分比，不重复播放整段绘制。
- `minimal` 图表设计保持轻量文字展示，不强制增加复杂绘制效果。

### 3. 在线状态与进度条

文件：`src/components/Node.tsx`、`src/components/UsageBar.tsx`、`src/components/UptimeKumaStatus.tsx`

- 在线/离线变化使用 Badge 内容交叉淡入，状态点仅在发生状态变化时做一次短环形扩散。
- 在线状态不使用永久脉冲；现有健康状态的持续表现保持不变。
- 资源条、流量条用 `transform` 或宽度过渡 350–500ms，避免突然跳变。
- 进度接近 0% 或 100% 时不产生额外弹性回弹，避免误读真实比例。

### 4. 图表和网络历史

文件：`src/components/MiniPingChart.tsx`、`src/components/AdaptiveChart.tsx`、`src/components/NodeMapView.tsx`

- `MiniPingChart` 首次显示时允许短暂淡入；后续数据更新保持线条连续，不整图重播。
- 最新数据点可以做一次小幅透明度强调，持续时间不超过 800ms。
- 地图区域状态变化只更新受影响国家/marker；新 marker 淡入，移除 marker 淡出，选中区域使用一次环形强调。
- 地图 hover 卡片继续跟随指针，不增加跟手延迟或弹跳。

## B：空间层次型

### 1. 节点网格和筛选

文件：`src/components/NodeDisplay.tsx`、`src/components/Node.tsx`

- 搜索、分组切换导致节点进入/离开时，使用 180–240ms 的透明度 + 轻微纵向位移。
- 同时存在多个节点时，入场错落最多 6 个元素，每个间隔约 40ms；超出部分不继续累加等待。
- 网格布局变化使用稳定的 `layout` 过渡，优先保持卡片位置连续。
- 只监听过滤结果或节点集合变化；`liveData` 的每次更新不能重置入场动画。
- 卡片 hover 只做轻微阴影、边框或内部图标位移，不做明显缩放，避免密集网格晃动。

### 2. 节点表格和排序

文件：`src/components/NodeTable.tsx`

- 用户主动排序时，行位置可以使用约 180ms 的重排过渡；数据轮询更新不移动整表。
- 表头排序图标继续使用现有方向动画，行高、列宽和展开详情占位保持不变。
- 搜索结果为空或恢复时，空状态和首行内容使用 160–200ms 淡入/淡出。
- 行展开沿用 Chevron 旋转和详情区域高度过渡，不叠加额外弹跳。

### 3. 顶部卡片、提示和地图段落

文件：`src/components/DashboardContent.tsx`、`src/components/DashboardCallouts.tsx`、`src/components/NodeMapView.tsx`

- 概览卡片可见性变化使用淡入/淡出，保留 grid 的固定间距。
- HTTPS、WebSocket 等 Callout 采用 180–240ms 的垂直滑入和离场淡出；提示内容变化不重新播放整页动画。
- 地图区域保持自身尺寸，marker 或 hover 面板的变化不能推动下方节点列表跳动。
- 首次加载仍使用骨架屏或既有 Loading，不用“成功动画”替代加载反馈。

## 动效节奏

| 场景 | 动效 | 时长 | 触发条件 |
| --- | --- | --- | --- |
| 纯数字变化 | 数值平滑过渡 | 250–350ms | 数值变化超过阈值 |
| 资源图表变化 | 圆环/柱/条过渡 | 350–500ms | 资源百分比变化 |
| 状态变化 | Badge 淡入、状态点短强调 | 180–360ms | 在线状态确实改变 |
| 卡片进入/离开 | 淡入淡出 + 小幅位移 | 180–240ms | 过滤结果或可见性改变 |
| 网格重排 | layout 位置过渡 | 180–220ms | 用户筛选/排序 |
| 最新图表点 | 透明度强调 | ≤800ms | 新数据点加入 |

不允许把持续轮询当作“卡片重新进入”，也不允许多个独立元素无限叠加延迟。

## 组件与数据流

- `DashboardContent` 负责概览卡片和页面分区的可见性变化，不新增全局动画状态。
- `NodeDisplay` 负责过滤结果集合和视图容器的空间过渡。
- `Node`、`AdaptiveChart`、`CircleChart` 负责单节点资源数值和图表变化。
- `NodeTable` 只在用户排序、展开和结果集合变化时做空间过渡。
- `NodeMapView` 只对实际变化的区域或 marker 做局部动画。
- 如果需要识别真实变化，优先使用节点 UUID、上一次数值引用或现有 hook；不引入全局事件总线。
- 动画组件不负责请求、轮询、Toast、错误判断或数据格式转换。

## 无障碍与兼容性

- 动态数字仍以可读文本呈现，不依赖颜色或动画才能理解。
- 节点状态、筛选 Tabs、表格排序和展开控件保留现有 ARIA 语义。
- 动效容器固定尺寸，文字和操作控件不会因为动画替换而跳动。
- `prefers-reduced-motion: reduce` 下关闭位移、缩放、路径绘制、状态点扩散和错落延迟。
- SSR/水合期间不依赖浏览器时间或随机值决定动画；客户端首次挂载只播放允许的一次入场。
- 在窄屏下优先保证内容可见，不因为动画改变横向滚动范围。

## 验证计划

1. 执行 `npx tsc --noEmit`、针对性 ESLint 和生产构建。
2. 手动验证 5 秒实时刷新时卡片不会反复入场，只有数值/进度变化。
3. 手动验证搜索、分组、排序、节点上下线和表格展开的过渡是否稳定。
4. 手动验证图表、地图 marker 和状态 Badge 的局部更新不会推动相邻内容跳动。
5. 在桌面端、移动端、深色模式和 reduced-motion 下检查布局、对比度和可感知状态。
6. 验证空状态、首次骨架屏、请求失败和网络恢复不会误显示成功反馈。

## 验收标准

- 仪表盘数据变化有可感知但不打扰的过渡。
- 节点列表筛选、排序、上下线和地图变化具有连续的空间反馈。
- 轮询不会重复播放整卡片入场动画，也不会因动画产生布局抖动。
- 所有动效均可在 reduced-motion 下安全降级。
- 不改变既有业务请求、错误处理、主题配置和语义图标反馈。
