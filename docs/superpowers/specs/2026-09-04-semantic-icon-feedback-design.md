# 第二阶段语义图标动画设计

- 日期：2026-09-04
- 状态：设计已批准，待规格审阅

## 背景

项目第一阶段已经建立了 `useActionFeedback` 和 `ActionFeedbackIcon`，并接入刷新、新增节点、编辑、复制和删除等异步操作。本阶段继续覆盖主面板、管理端和设置区域中仍然缺少语义反馈的图标操作。

本阶段不追求让所有图标都持续运动，而是根据动作性质选择反馈方式：会等待请求结果的动作显示加载、成功或失败；立即完成的界面状态切换使用短促的方向或交叉切换动画。

## 目标

1. 覆盖主面板节点操作、管理端操作和设置交互三组高频图标。
2. 异步操作统一使用现有的 `useActionFeedback` 和 `ActionFeedbackIcon`。
3. 同步状态切换使用 160–240ms 的轻量过渡，不显示没有语义依据的成功勾。
4. 保持成功状态约 800ms 后恢复原图标，失败状态显示 `X` 后恢复原图标。
5. 保留现有 Toast、错误文案、按钮禁用和数据请求职责，不让动画组件承担业务逻辑。
6. 在移动端、深色模式和 `prefers-reduced-motion` 下保持可用。

## 非目标

- 不给静态展示图标增加呼吸、悬浮或持续旋转动画。
- 不为纯客户端状态切换弹出 Toast 或伪造请求成功反馈。
- 不修改后端接口、登录协议、上传协议、节点数据结构或主题配置格式。
- 不引入新的动画依赖；优先复用 CSS keyframes、现有 Framer Motion 和第一阶段反馈组件。
- 不恢复或改动 Uptime Kuma 中已经有意删除的 Monitor ID 展示。

## 方案决策

采用“异步反馈 + 同步过渡”的分层方案。

### 异步反馈

登录、OAuth 登录、上传、重试、退出登录和真正提交设置等动作，在请求未完成时显示原图标旋转；成功显示 `Check`，失败显示 `X`，两种结果均保持约 800ms 后恢复。请求异常、非成功响应或业务返回失败都必须进入 error 状态，不能把网络请求的开始误判为成功。

异步按钮在 loading 时设置 `aria-busy="true"` 并阻止重复触发。导航会立刻卸载页面的动作只保证 loading 反馈和错误处理；如果页面在成功前完成导航，不要求强行显示成功勾。

### 同步过渡

展开/收起、排序方向、网格/表格切换、主题图标切换等立即完成的操作，不使用 success/error 状态，而使用短时的几何过渡：

- Chevron：围绕中心旋转 180°，约 200ms。
- 排序图标：方向切换或轻微位移，约 180ms。
- 网格/表格、太阳/月亮、调色板：固定尺寸容器内交叉淡入，约 160ms。
- Switch：保留原生 thumb 过渡；如果保存动作异步，再叠加第一阶段的 loading/success/error 图标。

所有同步动画都必须保持布局尺寸稳定，避免文字和相邻控件跳动。

## 接入范围

### 主面板节点操作

文件：`src/components/NodeDisplay.tsx`、`src/components/Node.tsx`

- 节点详情展开/收起：使用 `ChevronDown` 的旋转状态，并同步 `aria-expanded`。
- 排序按钮：使用 `ArrowUpDown` 或现有排序图标表达升序、降序和未排序，切换时做短促方向动画。
- 网格/表格视图：使用 `LayoutGrid` 与 `Table2` 在固定尺寸容器内交叉切换，并保留选中状态的可见表达。
- 节点标签或分组 Tabs：只做选中状态过渡，不为每次切换显示成功勾。

### 管理端操作

文件：`src/components/Login.tsx`、`src/components/UploadDialog.tsx`、`src/components/admin/AdminPanelBar.tsx`

- 登录和 OAuth：`LogIn` 在等待期间旋转；成功由导航或现有登录状态表达，失败显示 `X` 并保留错误文案。
- 上传：`Upload` 在提交期间旋转，上传成功显示 `Check` 约 800ms，失败显示 `X` 并保留现有错误提示；取消使用 `X` 或 `Ban` 的短促淡出，不伪造成功。
- 重试：`RefreshCw` 在请求期间旋转，结果通过 `Check`/`X` 表达；首次加载仍使用骨架屏，不播放成功动画。
- 退出登录：`LogOut` 只在请求期间显示 loading；如果随后跳转登录页，不等待成功图标，失败时保留当前页面并提示错误。
- 侧边栏展开/关闭：使用菜单图标与 Chevron 的几何过渡，不使用异步反馈。

### 设置交互

文件：`src/components/admin/SettingCard.tsx`、`src/components/admin/SettingCardMultiInput.tsx`、`src/components/ThemeSwitcher.tsx`

- 下拉选择：`ChevronDown` 随菜单展开旋转；如果 `OnSave` 返回 Promise，则接入 loading/success/error，否则只做选中项切换。
- 开关：保留开关 thumb 的原生过渡；异步持久化时在控件旁显示语义反馈，失败恢复原值并显示错误提示。
- 保存按钮：继续复用 `Save` → loading → `Check`/`X` 的统一反馈，成功状态保持约 800ms。
- 主题和布局：`Sun`/`Moon`、`Palette`、`LayoutGrid`/`Table2` 使用交叉切换；同步的本地设置不显示成功勾。
- 背景图上传或保存 URL：按异步上传/保存处理，成功和失败遵循第一阶段规则。

## 组件与数据流

- `ActionFeedbackIcon` 只负责根据状态展示图标和 CSS 动画。
- `useActionFeedback` 只负责局部状态、重复触发保护、800ms 恢复计时器和卸载清理。
- 业务组件负责请求、返回布尔结果、Toast、错误文案和失败时的值回滚。
- 同步过渡直接使用现有 `motion` 或 CSS class，不扩展异步反馈 Hook 的语义。
- 如果多个按钮处于同一列表中，每个独立请求维护自己的 Hook 状态，不能共享一个全局成功状态。

## 动画规格

| 动作类型 | idle | loading | 成功/结束 | 失败 |
| --- | --- | --- | --- | --- |
| 异步请求 | 原图标 | 原图标线性旋转，800ms/圈 | `Check` 约 800ms 后恢复 | `X` 抖动约 360ms，约 800ms 后恢复 |
| 展开/收起 | Chevron | 不适用 | 旋转 180°，约 200ms | 不适用 |
| 排序 | 方向图标 | 不适用 | 方向切换，约 180ms | 不适用 |
| 视图/主题 | 当前图标 | 不适用 | 固定容器内交叉淡入，约 160ms | 不适用 |
| 开关 | 当前状态 | 异步保存时才显示 | 保存成功时可显示 `Check` | 失败回滚并显示 `X` |

`prefers-reduced-motion: reduce` 下取消旋转、缩放、抖动和位移动画，只保留静态图标切换、文本状态和控件本身的语义状态。

## 错误、并发与兼容性

- 只有得到明确的成功响应后才显示 `Check`。
- loading 期间重复点击不发起第二个请求；同步状态切换不应因为重复点击产生异常状态。
- 设置保存失败必须恢复被乐观更新的值，不能只依赖红色图标。
- 上传、登录和退出登录等可能触发导航的操作，不在卸载后的组件上更新状态。
- 图标放在固定尺寸容器中，状态替换不能改变按钮宽度、高度或文本位置。
- 浏览器不支持 Clipboard、上传或其他能力时，保留现有错误处理并显示失败状态。

## 无障碍要求

- 异步 loading 按钮设置 `aria-busy="true"`，并使用 `disabled` 防止重复提交。
- 展开控件同步维护 `aria-expanded` 和对应内容关系。
- 网格/表格、主题和布局切换保留可见选中状态或 `aria-pressed`。
- 动画图标默认 `aria-hidden="true"`；动作名称、Toast 和错误文本承担可访问的状态说明。
- 状态不能只靠颜色区分；成功和失败均有图标变化，失败继续保留文字提示。

## 验证计划

1. 检查主面板展开、排序、视图切换在桌面端和移动端布局尺寸稳定。
2. 手动验证登录失败、上传成功/失败、重试成功/失败和退出登录异常。
3. 手动验证设置下拉、开关、保存按钮、主题和布局切换。
4. 验证异步操作 loading 期间不能重复触发，成功/失败状态约 800ms 后恢复。
5. 验证首次加载、静态切换和自动刷新不会误显示成功勾。
6. 在深色模式和 reduced-motion 设置下检查颜色、对比度和状态可感知性。
7. 执行 `npx tsc --noEmit`、针对性 ESLint 和 `npm run build`。

## 验收标准

- 主面板、管理端和设置区域的图标动画均与动作语义匹配。
- 异步操作统一遵循 loading → success/error → idle 的反馈节奏。
- 同步操作只播放短促的状态过渡，不伪造请求结果。
- 成功反馈约 800ms 后恢复原图标，失败反馈不会阻塞后续操作。
- 快速重复点击、请求失败、组件卸载和 reduced-motion 场景均无状态错乱。
- 不改变现有业务请求、错误文案、主题配置和 Uptime Kuma Monitor ID 的有意删除。
