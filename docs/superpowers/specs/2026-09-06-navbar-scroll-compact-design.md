# 滚动时导航栏紧凑化

## 已确认范围

页面顶部导航栏在用户向下滚动超过 16px 后进入紧凑态，继续 sticky 在视口顶部；回到顶部阈值以内时恢复完整态。导航栏仍保持当前左右布局、圆角毛玻璃背景、阴影和所有既有操作，不改为悬浮胶囊，也不在向下滚动时隐藏。

公告栏保持原有尺寸和内容，不参与本次收缩，避免公告内容因导航栏状态变化而重复跳动。导航栏外层的 sticky 结构和页面主内容不做额外重构。

## 状态与组件

`src/components/NavBar.tsx` 负责滚动状态，因为收缩视觉只属于导航栏，不需要新增全局状态或上下文。组件增加 `isCompact` 布尔状态：服务端和首次客户端渲染都以 `false` 为初值；客户端挂载后读取 `window.scrollY`，并注册带 `passive: true` 的 `scroll` 监听。监听器仅在是否跨过 16px 阈值时更新状态，组件卸载时移除监听，避免重复订阅。

状态只影响导航栏的尺寸类名，不影响 logo URL 校验、logo 加载失败回退、登录、语言、主题切换和剩余价值计算器等既有逻辑。

## 视觉行为

完整态继续使用当前尺寸：移动端内容区高度 64px，桌面端 80px。紧凑态使用更低的内容区高度：移动端约 48px，桌面端约 56px；同时收紧内边距和子元素间距，logo 从 32px 缩至约 28px，站点名字号适度降低。

所有操作按钮保留至少 36px 的可点击/触控尺寸，只压缩按钮之间的间距，不通过缩小图标或隐藏功能来节省空间。站点名使用现有单行布局策略；窄屏时继续由 flex 布局和现有内容长度约束处理空间竞争。

完整态与紧凑态之间沿用项目现有的 300ms transition 风格。收缩只改变导航内部尺寸，不改变公告栏的样式和逻辑；浏览器在正常情况下允许导航高度随状态平滑变化。

## 兼容性与可访问性

滚动状态只在 `useEffect` 中读取浏览器 API，避免 SSR/hydration 不一致。滚动监听使用被动模式，状态变化只发生在阈值边界，避免每个滚动事件触发实际渲染。

在 `prefers-reduced-motion: reduce` 下禁用导航栏尺寸过渡，保留最终尺寸切换和全部功能。收缩不改变 DOM 顺序、可见文本、焦点目标或 ARIA 语义；按钮的触控尺寸和键盘焦点样式保持不变。

## 验证

运行生产构建 `npm run build`，确认 TypeScript、Next.js 静态生成和占位符保护流程通过。手动验证以下场景：

- 页面位于顶部、滚动刚超过 16px、继续滚动、回到顶部；
- 桌面端和移动端宽度下的布局，尤其是长站点名和多个操作按钮；
- 浅色/深色主题、自定义 logo、logo 加载失败回退及私有站点登录入口；
- Tab 键焦点顺序、按钮可点击区域和公告栏内容是否保持稳定；
- 系统启用减少动效时，导航栏是否无过渡动画但仍能切换状态。

## 不在本次范围

不新增用户配置项、不改变导航栏功能、不压缩或隐藏公告内容、不实现向下隐藏/向上显示、不调整其他页面卡片或 Footer 的滚动行为。
